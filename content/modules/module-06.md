## จุดประสงค์การสอน

- **6.1 อธิบายหลักการและเขียนโปรแกรมสื่อสาร UART ได้**
- **6.2 เปรียบเทียบและใช้งาน I2C และ SPI ได้**
- **6.3 ออกแบบหน้าจอ HMI และโปรโตคอลคำสั่งอย่างง่ายได้**
- **6.4 ประยุกต์การสื่อสารกับเซนเซอร์และเซอร์โวในระบบอัตโนมัติได้**
- **จุดประสงค์เชิงพฤติกรรม เมื่อเรียนจบหน่วยนี้แล้ว ผู้เรียนสามารถ**
- **1) อธิบายเฟรม UART แบบ 8N1 และตั้งค่า UART ของ ESP32 ได้ (LLO7)**
- **2) ออกแบบหน้าจอ HMI และกำหนดชุดคำสั่ง ASCII ระหว่าง HMI กับไมโครคอนโทรลเลอร์ได้ (LLO7)**
- **3) เปรียบเทียบ UART, I2C และ SPI ได้ (LLO7)**
- **4) สแกนอุปกรณ์ I2C และอ่านค่าเซนเซอร์ได้ (LLO7)**
- **5) ควบคุมเซอร์โวด้วย PWM 50 Hz ได้ (LLO7)**
- **6) ออกแบบเครื่องสถานะของเซลล์อัตโนมัติอย่างง่ายได้ (LLO7)**

## 6.1 หลักการสื่อสารแบบ UART/USART

การสื่อสารแบบอนุกรมส่งข้อมูลทีละบิตผ่านสายน้อยเส้น ไมโครคอนโทรลเลอร์ใช้บ่อยสามแบบคือ
UART I2C และ SPI ดังภาพที่ 6.1 UART เป็นแบบอะซิงโครนัส ไม่มีสายนาฬิกา

## 6.6 การประยุกต์ใช้ไมโครคอนโทรลเลอร์ควบคุมระบบเมคคาทรอนิกส์

ระบบเมคคาทรอนิกส์รวมเซนเซอร์ ตัวควบคุม และแอคชูเอเตอร์ ตัวอย่างคือเซลล์คัดแยกชิ้นงาน
ซึ่งอ่านเซนเซอร์ผ่าน I2C/ADC สั่งเซอร์โวและสายพาน และส่งสถานะให้ HMI ผ่าน UART

## 6.7 การออกแบบโปรแกรมควบคุมระบบอัตโนมัติ

โปรแกรมควบคุมอัตโนมัติควรออกแบบเป็นเครื่องสถานะ มีสถานะรอ ทำงาน หยิบ
และความผิดพลาด พร้อมเงื่อนไขการเปลี่ยนสถานะที่ชัดเจน ดังภาพที่ 6.15
เมื่อเกิดความผิดพลาดต้องหยุดแอคชูเอเตอร์และรอรีเซ็ตจากผู้ปฏิบัติงาน

![ภาพที่ 6.15 เครื่องสถานะของเซลล์อัตโนมัติ](/images/book/b04_image101.png)

(ที่มา: ผู้จัดทำ)

![ภาพที่ 6.16 การต่อวงจรตัวอย่างของใบงาน: SHT30 เซอร์โว LED และ UART loopback](/images/book/b04_image102.png)

(ที่มา: ผู้จัดทำ)

### สรุปท้ายใบความรู้

\- UART ไม่มีสายนาฬิกา ต้องตั้งบอดเรตและเฟรมให้ตรงกัน และต่อ TX–RX ไขว้

\- HMI ต้องแสดงสถานะ ค่ากระบวนการ ปุ่มควบคุม และสัญญาณเตือนอย่างชัดเจน

\- I2C ใช้ SDA/SCL และแอดเดรส ส่วน SPI ใช้ SCK/MOSI/MISO/CS ความเร็วสูง

\- อ่าน SHT30 ผ่าน I2C แล้วแปลงค่าดิบเป็นหน่วยด้วยสูตรของผู้ผลิต

\- เซอร์โวใช้ PWM 50 Hz พัลส์ 0.5–2.5 ms แทนมุม 0–180°

\- ออกแบบระบบอัตโนมัติด้วยเครื่องสถานะที่มี FAULT

## บทสรุป

การสื่อสารแบบอนุกรมช่วยให้ไมโครคอนโทรลเลอร์แลกเปลี่ยนข้อมูลกับคอมพิวเตอร์ โมดูล
และเซนเซอร์โดยใช้สายน้อย UART
เป็นแบบอะซิงโครนัสที่ต้องตั้งค่าบอดเรตและรูปแบบเฟรมให้ตรงกัน ส่วน I2C
ใช้สองสายและแอดเดรสเลือกอุปกรณ์ และ SPI ใช้สัญญาณนาฬิกากับขา CS ให้ความเร็วสูง
หน้าจอ HMI ที่ดีแสดงสถานะ ค่ากระบวนการ การสั่งงานและสัญญาณเตือนอย่างชัดเจน
การรวมการสื่อสารกับเซนเซอร์และแอคชูเอเตอร์ เช่น เซอร์โวและสายพาน
ต้องออกแบบเครื่องสถานะและการจัดการข้อผิดพลาด

## แบบฝึกหัดท้ายหน่วยเรียน

คำชี้แจง: ให้นักศึกษาตอบคำถามต่อไปนี้ให้ถูกต้อง (10 ข้อ)

**1. จงคำนวณเวลาที่ใช้ส่งข้อความ "HELLO\n" (6 ไบต์) ที่ 9600 bit/s รูปแบบ 8N1**

<details><summary>เฉลย</summary>

6 ไบต์ × 10 บิต = 60 บิต ; เวลา = 60/9600 = 6.25 ms

</details>

**2. จงอธิบายความหมายของ UART 115200 8N1**

<details><summary>เฉลย</summary>

ความเร็ว 115200 bit/s ; 8 บิตข้อมูล ไม่มีพาริตี 1 บิตหยุด

</details>

**3. จงวาดเฟรม UART ของอักขระ A (0x41) โดยเรียงบิตจากซ้ายไปขวา**

<details><summary>เฉลย</summary>

start 0 ; data LSB-first 1,0,0,0,0,0,1,0 ; stop 1 → 0 10000010 1

</details>

**4. จงเปรียบเทียบ I2C กับ SPI อย่างน้อย 3 ประเด็น**

<details><summary>เฉลย</summary>

I2C: 2 สาย ใช้แอดเดรส ความเร็วต่ำกว่า ; SPI: 4+ สาย ใช้ CS ต่อสเลฟ เร็วกว่า ; I2C เหมาะเซนเซอร์ ช้า ๆ SPI เหมาะจอภาพ/SD card

</details>

**5. สแกน I2C พบ [0x3C, 0x44] จงคาดคะเนอุปกรณ์ที่ต่ออยู่**

<details><summary>เฉลย</summary>

0x3C น่าจะเป็นจอ OLED SSD1306 ; 0x44 น่าจะเป็น SHT30 (ควรยืนยันด้วยเอกสารของโมดูล)

</details>

**6. ค่าดิบความชื้น 0x8000 = 32768 จาก SHT30 คิดเป็น RH กี่เปอร์เซ็นต์**

<details><summary>เฉลย</summary>

RH = 100×32768/65535 ≈ 50.0 %

</details>

**7. ต้องการให้เซอร์โวไปที่ 135° ต้องใช้พัลส์กี่ ms และ duty_u16 เท่าใด**

<details><summary>เฉลย</summary>

ms = 0.5 + 135/90 = 2.0 ms ; duty = 2.0/20×65535 ≈ 6554

</details>

**8. จงออกแบบคำสั่ง ASCII 3 คำสั่งสำหรับควบคุมสายพาน**

<details><summary>เฉลย</summary>

RUN 1 (เริ่ม), RUN 0 (หยุด), SPD 60 (ความเร็ว 60 %) ; ตอบ OK หรือ ERR

</details>

**9. จงวาดเครื่องสถานะ 4 สถานะของเซลล์หยิบวางพร้อมเงื่อนไข**

<details><summary>เฉลย</summary>

IDLE→RUN เมื่อเริ่ม ; RUN→PICK เมื่อพบชิ้นงาน ; PICK→RUN เมื่อเสร็จ ; RUN→FAULT เมื่อเซนเซอร์ผิดปกติ ; FAULT→IDLE เมื่อรีเซ็ต

</details>

**10. เหตุใด HMI จึงควรแสดงหน่วยของค่ากระบวนการและบันทึกสัญญาณเตือน**

<details><summary>เฉลย</summary>

เพื่อให้ผู้ปฏิบัติงานตีความถูกต้องและตรวจสอบเหตุผิดปกติย้อนหลัง ลดความผิดพลาดในการสั่งงาน

</details>
